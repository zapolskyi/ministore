# План проєкту claude-store

Дата створення: 2026-08-08

---

## 1. Що будуємо

Комерційний інтернет-магазин на WordPress + WooCommerce з власною класичною темою.

| Параметр | Значення |
|---|---|
| Ринок | Україна |
| Мова | Одна — українська (`uk`) |
| Валюта | UAH (₴) |
| Каталог | 100–1000 товарів, з варіаціями (розмір/колір/тощо) |
| Платежі | LiqPay та/або WayForPay + оплата при отриманні |
| Доставка | Нова Пошта (відділення, поштомати, адресна) + самовивіз |
| Тема | Класична, з нуля, без білдерів |
| Адмін | Наповнення каталогу робить замовник через адмінку |

**Чого не робимо** (щоб не розповзалось): мультимовність, підписки, маркетплейс з кількома
продавцями, мобільний застосунок, кастомний headless-фронтенд.

## 2. Вихідна точка (станом на 2026-08-08)

Що вже є:

- WordPress **7.0.3**, чиста локальна інсталяція в Local by Flywheel
- Тема `my-theme` — **скелет із 90 файлів, усі порожні (0 байт)**. Структура продумана
  наперед: `inc/`, SCSS за схемою 7-1 з окремою папкою `shop/`, `template-parts/`,
  оверрайди `woocommerce/`
- Node.js v22.14.0, npm 10.9.2

Чого немає:

- **WooCommerce не встановлено.** Плагінів немає взагалі
- **Git не ініціалізовано** — жодної історії змін
- Немає `composer`, `wp-cli`, PHP CLI поза середовищем Local
- `package.json` порожній — збірки SCSS немає
- Хостинг не обрано, домену немає

Висновок: старт практично з нуля, але з готовим планом файлової структури. Це добре —
не доведеться переробляти архітектуру на середині.

## 3. Стек і обґрунтування

### Ядро

| Компонент | Вибір | Чому |
|---|---|---|
| CMS | WordPress 7.0.x | Дано |
| E-commerce | WooCommerce (остання стабільна) | Стандарт для WP, є всі українські інтеграції |
| Сховище замовлень | **HPOS** (High-Performance Order Storage) | Окремі таблиці замість `wp_posts`. На 1000+ товарів і зростаючій кількості замовлень різниця у швидкості адмінки суттєва. Вмикаємо **до** першого замовлення — потім міграція болючіша |
| Тема | Класична, власна | Контроль над розміткою і швидкодією. Блокова тема з WooCommerce досі має гострі кути, білдери дають −30 балів PageSpeed |
| Кастомні поля | Secure Custom Fields (SCF) | Форк ACF від WP-спільноти, безкоштовний, без ризику раптової зміни ліцензії. Групи полів експортуємо в `Local JSON` → потрапляють у git |
| Збірка CSS | dart-sass через npm | Без Webpack/Vite: тема класична, JS мало. Менше рухомих частин — менше поламається |

### Плагіни

Правило: **кожен плагін має виправдати своє існування.** Перед встановленням перевіряємо
дату останнього оновлення, кількість активних інсталяцій і сумісність із поточним WP.
Кожен доданий плагін фіксуємо в [DECISIONS.md](DECISIONS.md).

| Задача | Кандидати | Пріоритет |
|---|---|---|
| Платежі | Офіційний плагін LiqPay (Приватбанк), офіційний WayForPay | 🔴 |
| Доставка | Плагін інтеграції Нової Пошти з WooCommerce — обрати актуальний, звірити дату оновлення | 🔴 |
| Фіскалізація | Checkbox або Вчасно.Каса (ПРРО) | 🔴 при онлайн-оплаті |
| SEO | Rank Math (краща безкоштовна підтримка WooCommerce-схем) або Yoast | 🔴 |
| SMTP | FluentSMTP або WP Mail SMTP + Brevo/Postmark | 🔴 листи про замовлення мусять доходити |
| Об'єктний кеш | Redis Object Cache | 🟡 залежить від хостингу |
| Кеш сторінок | LiteSpeed Cache (якщо сервер на LiteSpeed) або FlyingPress/WP Rocket | 🟡 |
| Оптимізація зображень | ShortPixel / Imagify, або WebP на рівні сервера | 🟡 |
| Безпека | Wordfence або Solid Security + обмеження спроб входу | 🟡 |
| Бекапи | UpdraftPlus у зовнішнє сховище (S3/Backblaze) | 🔴 |
| Фільтри каталогу | Вбудовані блоки фільтрів Woo, або Filter Everything / YITH Ajax Filter | 🟡 |
| Імпорт товарів | Вбудований CSV-імпортер Woo; WP All Import — якщо структура складна | 🟡 |
| Товарний фід | CTX Feed / Product Feed PRO — для Google Merchant, Prom, Hotline | 🔵 |
| Форми | WPForms Lite або Contact Form 7 | 🟡 |

### Чого свідомо уникаємо

- Мультифункціональних «all-in-one» плагінів, що тягнуть по 50 фіч заради двох
- Преміум-тем і білдерів (Elementor, WPBakery) — це весь сенс власної теми
- Плагінів без оновлень понад рік
- Прямих правок ядра WordPress або WooCommerce

## 4. Архітектура теми

```
my-theme/
├── style.css                    заголовок теми (правил не містить)
├── functions.php                тільки константи + підключення модулів з inc/
├── inc/
│   ├── setup.php                add_theme_support, textdomain, розміри зображень, чистка <head>
│   ├── enqueue.php              стилі й скрипти, версії за filemtime, умовне підключення
│   ├── menus.php                позиції меню, атрибути пунктів
│   ├── woocommerce-setup.php    підтримка Woo, хуки, кастомізація циклів, AJAX-кошик
│   └── scf-fields.php           реєстрація груп полів, Local JSON
├── header.php · footer.php
├── front-page.php               головна: підключає секції
├── index.php · home.php · archive.php · single.php · page.php
├── page-about.php · page-cart.php · page-checkout.php
├── page-templates/              шаблони сторінок, що обираються в адмінці
├── template-parts/
│   ├── home/                    секції головної
│   ├── shop/                    картка товару, фільтри, сайдбар
│   ├── blog/ · about/ · contact/ · common/
├── woocommerce/                 оверрайди шаблонів WooCommerce
└── assets/
    ├── scss/                    7-1: abstracts, base, layout, components, sections, pages, shop, vendors
    ├── css/                     результат збірки — руками не редагувати
    ├── js/main.js
    └── img/
```

### Правила архітектури

1. **`functions.php` — тільки завантажувач.** Логіка живе в `inc/`. Файл більший за 30 рядків — сигнал, що щось пішло не так.
2. **Оверрайд шаблону WooCommerce — останній засіб.** Спершу шукаємо хук (`woocommerce_before_shop_loop`, фільтри). Кожен файл у `woocommerce/` — це технічний борг: при оновленні Woo його треба звіряти з оригіналом. Список оверрайдів ведемо в [DECISIONS.md](DECISIONS.md).
3. **Два CSS-бандли**: `style.css` (глобальний) і `woocommerce.css` (тільки на сторінках магазину). Не вантажимо стилі кошика на блог.
4. **Жодного inline-стилю в PHP.** Динаміка — через CSS-змінні.
5. **Увесь вивід екранується.** `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()`. Виняток — тільки те, що вже екранувало WooCommerce.
6. **Скелет файлів уже створено.** Заповнюємо порожні файли, а не вигадуємо нову структуру. Якщо файл виявився зайвим — видаляємо явно, з записом у PROGRESS.

| Дешевий шаред не потягне | Тайм-аути в години пік | Критерії хостингу в [DEPLOY.md](DEPLOY.md) — не економити на цьому |
