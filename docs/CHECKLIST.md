# Чекліст до релізу — claude-store

Робочий документ. Позначай `[x]`, коли пункт закрито. Порядок блоків = порядок робіт.

🔴 **блокер** — без цього не запускаємось · 🟡 **важливо** — перший тиждень після запуску · 🔵 **бажано**

## Фаза 0. Фундамент

### 0.1 Контроль версій

- [ ] `git init` у папці теми 🔴 — зараз історії немає взагалі, будь-яка помилка незворотна
- [ ] `.gitignore`: `node_modules/`, `assets/css/*.map`, `.DS_Store`, `*.log`, `.env`
- [ ] Вирішити, чи комітимо `assets/css/*.css` — так, комітимо: на шаред-хостингу може не бути npm
- [ ] Перший коміт зі скелетом («chore: initial theme skeleton»)
- [ ] Приватний віддалений репозиторій (GitHub/GitLab) 🔴 — локальний git не рятує від здохлого диска
- [ ] Гілки: `main` (прод) + `dev` (робота). Мерж у `main` = готовність до релізу

### 0.2 Збірка

- [ ] Заповнити `package.json`: `name`, `version`, `private: true`
- [ ] `devDependencies`: `sass`
- [ ] Скрипти: `scss` (разова), `watch` (спостереження), `build` (compressed, без source-map)
- [ ] Дві точки входу: `style.scss` → `assets/css/style.css`, `woocommerce.scss` → `assets/css/woocommerce.css`
- [ ] `npm install`, перевірити що збірка проходить

### 0.3 Локальне середовище

- [ ] PHP 8.2+ у налаштуваннях Local (звірити з майбутнім хостингом)
- [ ] `WP_DEBUG`, `WP_DEBUG_LOG`, `WP_DEBUG_DISPLAY = false`, `SCRIPT_DEBUG` у `wp-config.php`
- [ ] Query Monitor — бачити помилки й повільні запити 🟡
- [ ] `wp-cli` доступний (Local → Open site shell)

### 0.4 WooCommerce

- [ ] Встановити WooCommerce, пройти майстер налаштування
- [ ] **Увімкнути HPOS** 🔴 (WooCommerce → Налаштування → Додатково → Функції). Робити **до** першого замовлення
- [ ] Вимкнути «Наради» / маркетингові підказки Woo, `woocommerce_admin_disabled` 🔵
- [ ] Локація магазину: Україна, валюта UAH, символ ₴, роздільник — пробіл, 2 знаки після коми
- [ ] Українська локалізація WordPress і WooCommerce
- [ ] Одиниці ваги (кг) і розмірів (см) — потрібні Новій Пошті
- [ ] Створити сторінки Woo: магазин, кошик, оформлення, мій акаунт
- [ ] Створити тестові товари: простий, варіативний, зі знижкою, без залишку — на них тестуємо верстку

## Фаза 3. Магазин

### 3.1 Каталог

- [ ] `woocommerce/archive-product.php` — сітка, сортування, пагінація
- [ ] `template-parts/shop/product-card.php` — фото, назва, ціна, стара ціна, бейдж знижки, наявність, кнопка
- [ ] Плейсхолдер для товару без фото
- [ ] Фільтри: категорії, ціна, атрибути, наявність
- [ ] Фільтри працюють без JS (як GET-параметри) — SEO і надійність
- [ ] Перевірка `is_wp_error()` на `get_term_link()` у бічній панелі 🔵 — свідомо відкладено 2026-08-09. Ризик теоретичний (термін видалили між запитами), але тоді `esc_url()` отримає об'єкт і PHP впаде з fatal
- [ ] Стрілки пагінації — шеврони замість `←` `→` 🔵 — відкладено 2026-08-09. Woo друкує текстові стрілки, у макеті тонкі `‹ ›`. Найдешевше — фільтр `woocommerce_pagination_args` (6 рядків); альтернатива — оверрайд `woocommerce/loop/pagination.php`, але це ще один шаблон на звірку при оновленні Woo
- [ ] Теги, бренди й категорії перевести з посилань на архіви на `add_query_arg()` 🟡 — відкладено 2026-08-09. Зараз кожен клік **замінює** фільтр, бо архів терміна — окрема сторінка. Ціна вже працює правильно (`min_price`/`max_price`) і складається з рештою. Активний стан тоді визначати через `get_query_var()`, а не `get_queried_object_id()`
- [ ] Кнопка «Add to cart» у картці каталогу 🔴 — зараз це `<span>`, клік веде на сторінку товару. Потрібна `woocommerce_template_loop_add_to_cart()`; тоді `.product-card__media` має стати `<div>`, бо Woo друкує `<a>`, а посилання в посиланні невалідне
- [ ] Зображення товарів через `$product->get_image()` 🟡 — зараз `<img>` збирається вручну: немає `srcset`, а в атрибутах написано 600×600 при реальному розмірі 300×300
- [ ] Рівні заголовків у каталозі 🟡 — назви товарів `h3` одразу після `h1`, пропущено `h2`
- [ ] AJAX-оновлення сітки 🟡
- [ ] Сторінки категорій: опис, банер, SEO-текст під сіткою
- [ ] Пошук по товарах, що не повертає сміття
