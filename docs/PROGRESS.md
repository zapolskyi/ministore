## 🪤 Граблі

Несподіванки, на яких втратили час. Записуємо одразу, бо забувається за тиждень.

| Дата | Проблема | Рішення |
|---|---|---|
| 2026-08-09 | PHP-скрипт із `wp-load.php` падав з «Error establishing a database connection», хоча сайт у браузері працював | Local тримає MySQL на unix-сокеті, а не на `localhost`. Запускати PHP із `-d mysqli.default_socket=~/Library/Application Support/Local/run/<ID>/mysql/mysqld.sock`. ID сайту — в `~/Library/Application Support/Local/sites.json` |
| 2026-08-09 | WooCommerce ігнорував `woocommerce/archive-product.php` з теми — магазин малювався як звичайна сторінка | Потрібен `add_theme_support( 'woocommerce' )`. Без нього Woo вважає тему несумісною і не бере шаблони з папки теми взагалі |
| 2026-08-09 | Шість сторінок (`/about/`, `/contact/`, `/blogs/`, `/cart/`, `/checkout/`, `/my-account/`) віддавали **0 байт** — повністю порожню відповідь | У корені теми лежали заготовки на 0 байт: `page.php`, `single.php`, `archive.php`, `home.php`, а також `page-cart.php` і `page-checkout.php`, які за ієрархією WordPress перехоплюють свої слаги **раніше** за `page.php`. Порожній шаблон = порожня сторінка без помилки. Порожні видалити (тоді спрацює `index.php`), `page.php` написати |
| 2026-08-09 | Кнопки «Add to cart» і «Buy Now» ніби нічого не робили | Товар додавався, але не було двох речей: хука `woocommerce_before_single_product` (він друкує повідомлення Woo) — загубився, коли ми замінили `content-single-product.php` на власний файл; і лічильник у шапці був захардкоджений `(0)`. Лічильник тепер живий, плюс фрагмент `woocommerce_add_to_cart_fragments` оновлює його після AJAX-додавання з каталогу |
| 2026-08-09 | Порожні файли-заготовки в `woocommerce/` мовчки вимкнули функції магазину: у простих товарів зникла кнопка «В кошик», у варіативних — кількість і кнопка, кошик і оформлення виводились порожніми | Woo вважає оверрайдом будь-який файл із потрібним ім'ям, незалежно від вмісту. Порожній файл = порожній вивід **без помилок**. Видалити. У `woocommerce/` не має бути файлів на 0 байт — заготовки тримати поза цією папкою |
| 2026-08-09 | `get_template_part()` не знаходив файл — сторінка товару рендерилась порожньою | Шлях рахується **від кореня теми**, а не від папки поточного файлу: `get_template_part( 'woocommerce/single-product/product-main' )`. Функція не кидає помилку, коли файлу немає |
| 2026-08-09 | На сторінці товару `$product` виявився рядком, fatal `get_name() on string` | WordPress копіює всі query vars у глобальні змінні, а на `/product/slug/` query var зветься `product`. Об'єкт `WC_Product` туди кладе WooCommerce лише після `the_post()`. Тому цикл `have_posts()` у `single-product.php` обов'язковий |
| 2026-08-09 | `get_template_part()` мовчки нічого не підключав — сторінка товару рендерилась порожньою між шапкою й підвалом | Шлях рахується **від кореня теми**, а не від папки поточного файлу. Треба `get_template_part( 'woocommerce/single-product/product-main' )`. Функція не кидає помилку, коли файлу немає — тільки порожнеча в розмітці |
| 2026-08-09 | Після переходу меню на `wp_nav_menu()` зникли всі стилі навігації | WordPress друкує власні класи (`menu-item`, `sub-menu`) і не додає класів посиланням. BEM-класи дописані фільтрами `nav_menu_css_class`, `nav_menu_link_attributes`, `nav_menu_submenu_css_class` в `inc/menus.php` |
| 2026-08-09 | Замість каталогу й товару віддавалась заглушка «Great things are on the horizon» | WooCommerce після встановлення вмикає режим **Coming soon** (`woocommerce_coming_soon = yes`) і перехоплює сторінки магазину. Перемикається в WooCommerce → Налаштування → Загальні → Видимість сайту → Live |

## 2026-08-09 — кошик і аналіз стану проєкту

**Фаза:** 3 · **Витрачено:** ~3 г

**Зроблено**

- Галерея товару переведена на `woocommerce_show_product_images()` + три
  `add_theme_support( 'wc-product-gallery-*' )`: зум, лайтбокс, мініатюри,
  підміна фото при виборі варіації
- Схожі товари через `wc_get_related_products()`
- Головна: добірка товарів тепер із реальних даних, керується зіркою
  «Рекомендований» в адмінці
- Стандартні стилі WooCommerce вимкнено — 120 КБ CSS, який перебивав нашу
  верстку специфічністю (ADR-010)
- `page.php` написано, порожні шаблони кореня видалено — шість сторінок
  віддавали 0 байт
- Кошик: сторінку переведено з блоків на шорткод (ADR-011), `cart.php` і
  `cart-empty.php` з повним функціоналом. Перевірено наскрізно: зміна
  кількості, видалення, купон, підсумки, лічильник у шапці
- Повідомлення Woo повернуто на сторінку товару, лічильник кошика став живим

**Аналіз стану**

Готово: каркас теми, головна, каталог із фільтрами й пошуком, сторінка товару
з варіаціями, кошик. Фази 0–2 закриті, фаза 3 приблизно на 70 %.

Головні блокери на сьогодні:

| | Що | Чому критично |

| 🔴 | Git не ініціалізовано | шість тижнів роботи в одному екземплярі |
| 🔴 | Жодного способу оплати | замовлення не можна оформити взагалі |
| 🔴 | Мова сайту `en_US` | магазин у гривні з англійським інтерфейсом |
| 🔴 | Оформлення на блоках | наша верстка туди не застосовується |

**Фаза:** 1 · **Витрачено:** ~1 г

**Зроблено**

- Встановлено WooCommerce 11.0.0 і Secure Custom Fields (зробив замовник).
  HPOS увімкнено, валюта UAH, країна Україна
- Верстку перенесено зі своїх шаблонів сторінок у файли, які WooCommerce
  шукає сам:

  | Було | Стало | Що це |
  |---|---|---|
  | `page-templates/page-shop.php` | `woocommerce/archive-product.php` | каталог, категорії, теги |
  | `template-parts/shop/product-card.php` | `woocommerce/content-product.php` | одна картка в сітці |
  | `page-templates/page-product.php` | `woocommerce/single-product.php` | сторінка товару |

- Додано `add_theme_support( 'woocommerce' )` — без нього шаблони з теми не працюють
- Зі сторінки магазину знято призначений вручну шаблон, тимчасову сторінку
  `/product/` відправлено в кошик
- Режим Coming soon вимкнено

**Свідомо не робили**

- Хуки WooCommerce, цикл товарів і реальні дані. Зараз у шаблонах статичні масиви —

## 2026-08-09 — верстка головної, каталогу та сторінки товару

**Фаза:** 1 · **Витрачено:** ~3 г

**Зроблено**

- Каркас теми: `style.css` (заголовок), `functions.php` (тільки константи + `require`),
  `inc/setup.php`, `inc/enqueue.php`, `header.php`, `footer.php`, `index.php`
- Збірка SCSS: `package.json` зі скриптами `scss` / `watch` / `build`, dart-sass встановлено.
  Два бандли — `style.css` (усі сторінки) і `woocommerce.css` (тільки товарні сторінки)
- Зверстано три сторінки:
  - **Головна** — `front-page.php` + секції `hero`, `benefits`, `featured-products`
  - **Каталог** — `page-templates/page-shop.php`, сітка 3×3, бічні фільтри, пагінація
  - **Товар** — `page-templates/page-product.php`, галерея, вибір кольору й розміру,
    лічильник кількості, вкладки, схожі товари
- Спільні блоки винесені й використовуються повторно: `product-card`, `section-bar`,
  `products-slider`, `newsletter`, `insta`, `breadcrumbs`
- JS ванільний, без jQuery: бургер, мобільне підменю, лічильник кількості,
  вибір варіацій, вкладки, слайдери зі стрілками й крапками
- Заглушки зображень: 4 SVG в `assets/img/` — замінити на реальні фото
- Створено сторінки `/shop/` і `/product/` у WordPress, увімкнено ЧПУ `/%postname%/`

**Перевірено**

- `php -l` по всіх файлах теми — синтаксичних помилок немає
- `/`, `/shop/`, `/product/` віддають HTTP 200, у розмітці немає PHP-помилок
- `woocommerce.css` підключається лише на головній, у каталозі та на товарі

**Проблеми**

- WordPress з CLI не бачив базу: Local тримає MySQL на сокеті, а не на `localhost`.
  Рішення записано в «Граблі»

**Рішення**

- Верстка живе в `page-templates/`, бо WooCommerce ще не встановлено.
  У фазі 3 ця сама розмітка переїде у `woocommerce/archive-product.php`
  і `woocommerce/single-product.php`, а масиви замінить цикл Woo
- Шрифт Jost із Google Fonts — найближчий до макета геометричний гротеск.
  У фазі 6 варто перевести на локальний, щоб прибрати сторонній запит

**Наступний крок**
